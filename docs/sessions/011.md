# Session 011

Date: 2026-10-02
Branch: `feat/chunk-streaming`

## Goal

Implement Milestone 12: Dynamic Chunk Loading and Unloading around player.

## What was done

- **ChunkManager refactor (`src/chunk_manager.zig`):**
  - Replaced static `NxN` slice allocation with dynamic hash map `std.HashMap(ChunkCoord, LoadedChunk, ChunkCoordContext, 80)`.
  - Added `ChunkCoord` struct with hash + eql.
  - Implemented `update(player_x, player_z)`: calculates player chunk coordinate and calls `syncToCenter`.
  - Implemented `syncToCenter`:
    - Purges out-of-range chunks (unloads mesh/VAO/VBO via `ChunkRenderer.deinit`).
    - Generates new terrain chunks inside view radius `[-radius, +radius]`.
    - Marks adjacent neighbors dirty on new chunk insertion so cross-chunk border faces cull properly.
    - Incremental meshing budget (up to 4 dirty chunks per frame during gameplay, unlimited on startup).
  - Preserved `draw` (frustum culling + translation), `isSolidWorld`, `setBlockWorld`, and `editAndRemesh`.
  - Added unit tests for `ChunkCoord` hash/eql, streaming load/purge filter, and negative chunk coord indexing.
- **Main loop integration (`src/main.zig`):**
  - Configured radius 3 (7x7 = 49 chunks around player).
  - Added `manager.update(player.pos.x, player.pos.z)` to game loop every tick.
  - Debug HUD shows loaded chunk count alongside drawn/culled stats.
- Verified build and tests pass (`zig build test`).
- Verified binary runs with OpenGL context (`zig build run` / headless timeout test confirms 49 loaded chunks, ~20 drawn, ~29 culled, 75+ FPS).
